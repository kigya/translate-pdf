The Android PDF lifecycle test first reproduced a crash after a failed Word-page draw: an unfinished PDF page was closed. Rendering now creates the bitmap before opening a PDF page and always finishes an opened page. The physical happy-path and injected Exception/OOM cases pass after that repair. Another regression confirms that canceling a persisted paused job after process restart releases an idle service, allowing a new job to start.

Word export warnings no longer acquire a literal `null; ` prefix when the first page has no earlier error. Red regressions also reproduced missing DOCX resource checks and cancellation races. Low-memory, low-disk and allocation failures now pause at saved checkpoints; cancellation wins over resource callbacks and export completion. Terminal state and export metadata commit atomically. Failed or canceled exports remove only new unpublished artifacts, preserving earlier published files. Saved DOCX segments can export without loading model weights. These changes pass the full Android run and independent review.
